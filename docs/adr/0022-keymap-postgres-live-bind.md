# ADR-0022 — KeyMap live Postgres bind (wizard, attrs, scale)

## Status

**Accepted** (implemented — OpenSpec `specs/keymap-live-bind/`)

## Context

ADR-0020 already allows KeyMap `storage=source` with Postgres write-back, but the MVP path is thin:

- Editor binds schema/table/`from_column`/`to_column` inline (no bind wizard).
- Rows are `{from,to}` only — extra WH columns are ignored and **destroyed** by full DELETE+INSERT.
- Preview uses VALUES from cached `entries`; at **100K** (stress fixtures in `scripts/stress/`) that pattern and full-snapshot Save do not scale.
- Fuzzy matcher already allows up to **250K** keys/side; live SoT must not copy the whole dictionary into `.dwhproj.json`.

Product need: explicitly bind an existing Postgres mapping table, choose From/To columns (any names), choose which other columns are editable, and Save without wiping serial PK / unselected columns — at stress scale.

## Decision

1. **Writable live SoT = Postgres only.** Parquet/CSV are not writable KeyMap backends in this ADR (see Future).
2. **Bind wizard** when creating/rebinding a source KeyMap: connection → schema.table → describe columns → pick **From** and **To** → whitelist **editable attributes**. Default whitelist: all non-autogenerated columns except From/To (serial/identity unchecked).
3. **IR:** `KeyMapDef.editable_columns: string[]`; `KeyMapEntry.attrs` for attribute values. ApplyKeyMap / dbt join remain **From→To only**.
4. **Row key on write = From** (unique KeyMap rule). **Not** full-table wipe.
5. **Scale split:**
   - `storage=seed`: small/medium; full `entries` in project OK.
   - `storage=source`: WH is SoT; project must **not** hold the full dictionary. Editor uses **paged/filtered** reads; session **dirty delta** (upserts + deleted froms); Save applies **batched** SQL (temp/`UNNEST`/set-based upsert — not one execute per row).
6. **Preview for source:** join the **ATTACH**’d Postgres map relation; do not embed 100K VALUES. ApplyKeyMap must not snapshot the full table into project JSON.
7. **Concurrency:** avoid whole-map hash of 100K as the only gate; prefer table version / from-level checks as implementation matures.
